# Markoob for Firefox — 视觉规范

> **⚠ v1 存档**：v2.0 的视觉以 `shared/tokens.css` 当前令牌与 `newtab/newtab.css` 的实际实现为准（暖灰中性色板、卡片式列表、一页式设置）。本文中关于行/列布局、密度、字号、宽度等可变项的章节已不反映现状，保留作历史参考。

> 设计：design-architect · 令牌实现：`shared/tokens.css` · 可视化：`docs/visual-preview.html`
> 本文件是颜色、字号、间距、组件外观的**唯一裁决源**。任何数值改动先进 `tokens.css`，再回改本文件。

---

## 1. 视觉概念

**一句话：一张被长期使用的阅读桌——纸是主区，桌沿是侧栏，字是墨，其余全部让路。**

三个关键词：**纸 · 墨 · 秩序**

用户每次打开新标签页只停留 2–5 秒，动机是「去某个地方」。所以这套视觉的成败标准不是"第一眼惊艳"，而是**第二十次打开时仍然不烦**。所有装饰都必须能回答一个问题：它是否帮助用户更快找到并打开书签。回答不了就删。

由此推出三条硬约束：

1. **不做仪表盘。** 没有 hero、没有大标题、没有卡片阴影堆叠、没有"欢迎回来"。首屏第一视觉重量是搜索框，第二是书签本身。
2. **不用"科技感"。** 无渐变、无毛玻璃、无霓虹、无紫色、无彩色阴影。明暗两套都靠**明度与细线**建立层级。
3. **层级靠三样东西：留白、1px 细线、字重。** 不靠色块、不靠投影、不靠圆角大小。

### 1.1 结构隐喻（可被感知，不可被看见）

| 层 | 令牌 | 语义 |
|---|---|---|
| 桌沿 | `--bg` | 侧栏、页面边缘。比纸暗一档 |
| 纸 | `--canvas` | 主内容区。用户的"桌面" |
| 卡片 | `--surface` | 落在纸上的索引卡 |
| 笔迹 | `--line` / `--line-strong` | 1px 分隔与描边 |
| 墨 | `--text` → `--text-tertiary` | 三级墨色 |
| 印泥 | `--accent` | 只用于焦点、选中、主按钮 |

隐喻不画出来、不加纹理、不做纸张噪点——只在明度关系上成立。**禁止**加任何 bg image / noise / texture。

### 1.2 招牌细节（全产品只有这一个）

**「色脊」— 文件夹的彩色书脊。**

每个文件夹按名称哈希分配 6 种低饱和墨色之一（`--spine-1…6`），渲染为该文件夹行/卡**左缘的一条 2px 竖线**（高 16px，圆角 1px），像档案夹上的彩色标签。

- 位置：只在**左侧文件夹树**和**文件夹卡片**上出现。书签卡片没有颜色。
- 尺寸：未选中 2px / 55% 不透明度；悬停 2px / 70%；选中 3px / 100%。
- 为什么是它：颜色带来"这个文件夹在哪"的肌肉记忆，但只占据 2px、只出现在导航区，不进入用户的扫读路径。**它有功能，所以不删。**
- 除它之外，禁止第二个装饰性母题（不要再加折角、不要加编号、不要加角标、不要加锯齿）。

### 2.4 色彩纪律

- 一个屏幕里 `--accent` 出现面积**不超过 3%**：焦点环、选中脊、主按钮、链接文字。
- 功能色（success/danger）**不用于装饰**，只在语义成立时出现。
- 不用纯黑 `#000`、不用纯白 `#FFF` 作大面积底色（`--accent-contrast` 的 `#FFFFFF` 只作按钮文字）。
- 深浅两套的**相对层次关系必须一致**：canvas 永远比 bg 亮一档，surface 永远比 canvas 亮一档。

## 3. 字体

字体族：`--font-ui` = `"Lexend"` → `-apple-system` → `"Segoe UI"` → `"PingFang SC"` → `"Noto Sans SC"` → `"Microsoft YaHei"` → `sans-serif`。
Lexend 只本地打包（4 个字重，`font-display: swap`），中文走系统字体。**禁止**任何网络字体。

| 令牌 | px / 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| `--fs-2xs` | 11 / 14 | 500 | +0.02em | 快捷键胶囊（`⌘K`），仅拉丁 |
| `--fs-xs` | 12 / 16 | 500 | +0.04em | 区块标签、计数、域名、meta |
| `--fs-sm` | 13 / 18 | 500 | 0 | 菜单项、文件夹树行、小按钮、字段标签 |
| `--fs-md` | 14 / 20 | 400 | 0 | 正文、搜索输入、说明文字 |
| `--fs-bookmark-title` | 13–17（默认 14）/ 1.35 | 500 | 0 | 书签卡片标题，受设置「书签字号」控制 |
| `--fs-lg` | 16 / 22 | 600 | 0 | 对话框标题、弹窗标题、抽屉标题 |
| `--fs-xl` | 20 / 26 | 600 | 0 | 引导步骤标题 |
| `--fs-2xl` | 24 / 30 | 600 | -0.005em | 仅引导封面 |

补充规则：

- 字标：`Markoob` 用 15px / 600 / `-0.01em`，配 16px 内联 SVG 标记。**不做大字号品牌区。**
- 数字一律 `font-variant-numeric: tabular-nums`（计数、尺寸、版本号）。
- 中文不使用 `text-transform: uppercase`（无效且会误伤英文混排）；区块标签改用 12px/600 + `0.04em` 字距建立"标签感"。
- 标题最多 1 行 + 省略号；域名最多 1 行 + 省略号。**不换行、不撑高**——等高网格是扫读的基础。
- 不用 700 作正文/标题；700 只留给未来可能的引导封面。

## 4. 间距、圆角、阴影、动效

### 4.1 间距（4px 基准）

`2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64` = `--sp-05 … --sp-16`

| 场景 | 值 |
|---|---|
| 图标与文字 | 8 |
| 控件内水平内边距（按钮 32 高） | 12 |
| 卡片内边距 | 12 |
| 卡片之间（栅格 gap） | 12 |
| 区块之间 | 28 |
| 内容区左右边距 | 32 |
| 抽屉/对话框内边距 | 20 |
| 菜单项内边距 | 8（左右）/ 项间 2 |

规则：组件内部一切为 4 的倍数；同一个视觉组内只用**一个**间距值；禁止用 margin 造空格，用父级 `gap`。

### 4.2 圆角

| 令牌 | 值 | 用途 |
|---|---|---|
| `--r-xs` | 2 | 色脊、快捷键胶囊、拖拽插入线、滑块 |
| `--r-sm` | 4 | 按钮、输入、菜单项、图标砖 |
| `--r-md` | 6 | 卡片、菜单、Toast、浮层 |
| `--r-lg` | 10 | 对话框、引导卡 |
| `--r-full` | 999 | 仅计数胶囊、开关轨道 |

禁止：卡片圆角 > 6、按钮做成胶囊、嵌套圆角不递减（内圆角 = 外圆角 − 内边距）。

### 4.3 阴影（最轻，最多 2 层，永不彩色）

| 令牌 | 值 | 允许出现的位置 |
|---|---|---|
| `--shadow-1` | `0 1px 2px rgba(33,30,25,.06), 0 1px 0 rgba(33,30,25,.03)` | 几乎不用；仅常驻浮起的控件 |
| `--shadow-2` | `0 8px 24px -8px rgba(33,30,25,.18), 0 2px 6px rgba(33,30,25,.07)` | 菜单 / 对话框 / 抽屉 / Toast |

**卡片永远无阴影。** 卡片层级由 `--surface` 与 1px `--line` 表达，悬停只换底色和描边。深色模式阴影几乎不可见，因此深色下浮层额外加 1px `--line-strong` 描边保证边缘可辨。

### 4.4 动效

| 令牌 | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 110ms | 悬停变色、按下 |
| `--dur-base` | 160ms | 浮层出现、菜单展开 |
| `--dur-slow` | 220ms | 对话框、抽屉 |
| `--ease-out` | `cubic-bezier(.2,.65,.25,1)` | 进场 |
| `--ease-in-out` | `cubic-bezier(.45,0,.25,1)` | 位移/展开 |

允许动画的属性只有：`background-color`、`border-color`、`color`、`opacity`、`outline-color`。
浮层入场允许 `opacity 0→1` + `translateY(-2px)→0`（160ms）。**卡片层禁止 transform**、禁止 hover 上浮、禁止 scale 放大、禁止 stagger 瀑布。
`prefers-reduced-motion: reduce` 或设置里「关闭书签动效」（`[data-motion="off"]`）时全部时长归零。

## 5. 布局与密度

```
┌──────────┬──────────────────────────────────────────┐
│          │ 顶栏 56：搜索 40 + 右侧控件               │
│ 侧栏     ├──────────────────────────────────────────┤
│ 232      │ 内容区 padding 32/20，max 1560            │
│ (196–320)│  ┌ 置顶 ─────────────────────────────┐    │
│ 可拖拽   │  ┌ 为你推荐 ────────────────────────┐    │
│ 可折叠   │  ┌ 全部/当前文件夹 ─────────────────┐    │
└──────────┴──────────────────────────────────────────┘
```

侧栏宽 `232`（`--sidebar-w-default`），拖拽范围 `196–320`，写入 `storage.local`。窗口 < 1080px 自动折叠（宽 0，顶栏左侧保留 32×32 展开按钮）。

### 5.1 列数与密度（row 布局 / card 样式）

计算基准：内容宽 = 窗口 − 侧栏 − 64（左右 32），`--card-min: 190`，gap 12，内容宽上限 1560。

| 窗口宽 | 内容宽 | 列数 | 卡片宽 | 每屏行数（1080 高） | 一屏可见书签 |
|---|---|---|---|---|---|
| 900（侧栏折叠） | 836 | 4 | 200 | ~9 | 36 |
| 1280 | 984 | 4 | 237 | ~9 | 36 |
| 1600 | 1304 | 6 | 207 | ~9 | 54 |
| 1920 | 1560（封顶） | 7 | 213 | ~9 | 63 |

- 卡片宽控制在 **190–240**：低于 190 标题只剩 6–8 个汉字，高于 240 一眼扫过的信息密度下降。
- 1920 起内容区封顶 1560 并**左对齐**（不居中）——与左侧树对齐的视觉基线比居中更稳。
- 列数封顶 7，不再增加；多余空间给留白。
- 实现建议：`grid-template-columns: repeat(auto-fill, minmax(var(--card-min), 1fr))`，`--card-min` 由设置「书签宽度」在 160–320 间调。

**低于 900（低于 PRD 声明的最小宽度，仅作退化，不作目标态）——v0.2 补充，ux-spec V7 签字：**

| 窗口宽 | 规则 |
|---|---|
| 1080–1079 | 侧栏自动折叠（宽 0，顶栏左侧出现 32×32 展开按钮） |
| 760–1079 | 内容区左右 32 不变；网格照常 auto-fill（760 时 3 列 ≈ 232） |
| ≤760 | 内容区左右降为 20；网格强制**单列**，但**卡片限宽 `max-width: 320px`（card）/ `480px`（compact）并左对齐**——单列拉满会在 700px 宽处出现一条 700px 长的"横幅卡片"，比多列更难读；侧栏改为覆盖式抽屉，不再挤压内容宽度 |
| 高度 `< 600` | 推荐区整块隐藏（P1：信息展示型区块让位给"我的内容"）；**置顶区最多保留 1 行**，超出走 §6.3 的「还有 N 项」追加控件。隐藏后若置顶区也为空，内容起点直接上移到内容区顶部内边距，**不留空槽、不留标题** |

窄窗下不改变任何组件内部尺寸（卡片仍 68 高、菜单仍 216 宽），只改列数与边距——避免为了窄窗再造一套规格。

### 5.2 其他布局模式

| 模式 | 规则 |
|---|---|
| row × compact | `minmax(260, 1fr)` → 1280:3 列(320) / 1600:4 列(314) / 1920:5 列(293) |
| column × card | CSS multi-column，`column-width: 190px`，`break-inside: avoid`，列内垂直堆叠 |
| column × compact | `column-width: 260px` |
| 推荐区 | 固定 ≤3 列，`minmax(260,1fr)`，容器宽 `--rec-max: 900px`，最多 6 条（2 行） |

## 6. 组件视觉规范

所有尺寸单位为 px；"层级"指视觉重量顺序，非 z-index。

### 6.1 左侧文件夹树（sidebar）

- 行高 **30**，左右内边距 **8**，行间距 **0**，圆角 **4**（整行 hover 底）。
- 结构：`色脊(2×16) · 8 · 折叠箭头(14) · 6 · 文件夹图标(16) · 8 · 名称(flex) · 6 · 计数(12)`。
- 层级缩进：每级 **+14**，色脊对齐到该行缩进起点。
- 名称：13 / 500；空闲 `--text-secondary`，悬停 `--text`，选中 `--text`（字重不变，靠底色与色脊区分）。
- 计数：12 / 400，`--text-tertiary`，`tabular-nums`，右对齐，最小宽 20；为 0 时**隐藏**（不显示 "0"）。
- **计数口径（v0.3 定，ux-spec §5 询问项）：一律递归，即"含子文件夹共 N 项"。** 三处必须同源——侧栏行的计数、文件夹卡片副行、区块标题里的计数——**不允许出现同一文件夹两个数字**。判据也同源：`hideEmptyFolders` 隐藏的正是递归计数为 0 的夹，与显示的数字是同一个值（不能显示用一个、隐藏用另一个）。理由：树是"去哪"的地图，用户扫描时问的是"这里有多少东西"，只含 1 个子夹但里面 200 条的夹若显示「1」，会把人劝退。视觉上不需要为"递归"加任何新符号（不加 `+`、不加 `Σ`），文案层用 `aria-label="共 200 项，含子文件夹"` 说明即可。
- 状态：
  - 空闲：底色透明，色脊 2px / 55%
  - 悬停：`--surface-hover`，色脊 2px / 70%
  - 选中：`--surface-active`，色脊 3px / 100%，箭头指向展开
  - 拖拽悬停（书签拖进文件夹）：`--accent-soft` 底 + 内描边 1px `--accent` + 色脊 3px —— 三者同时给，因为目标行必须一眼可辨
  - 键盘焦点：`2px --focus` 环，offset 2
- 分组：`全部书签` 为首行（无脊，用 16px 网格图标）；其下依次为 工具栏 / 书签菜单 / 未分类 / 移动端，各自带脊。
- 侧栏顶部：字标 15/600 + 16px 标记，高 56（与顶栏同高，形成一条水平基线）。
- 侧栏底部：`设置` 行（30 高，无脊，齿轮 16）常驻，不随树滚动。
- 拖拽调宽手柄：宽 4，悬停/拖拽时显示 `--line-strong` 竖线，`cursor: col-resize`，z-index 30。
- **展开 / 折叠的动效（v0.3 补充）**：树展开是**行的插入**，不是高度动画——子行以 `opacity 0 → 1` 在 `--dur-base`（160ms）内淡入，**不做 height / max-height 过渡**（30px 行列表做高度动画必然抖，且会带动下面所有行位移）。折叠同理：子行淡出后立即从文档流移除，不要等动画结束再移除。
- **注意区分"延迟"和"时长"**：拖拽悬停 600ms 自动展开是**交互延迟**（JS 计时器常量），不是动效时长，不进 tokens.css 的 `--dur-*`；那 600ms 到点后的展开动画仍然走 160ms。混用会让"动画变慢"和"反应变迟钝"变成同一个旋钮，调不动。

### 6.2 顶部搜索框

- 高 **40**，`--r-sm`，宽 `clamp(280, 34vw, 420)`，左对齐到内容区左基线。
- 静息：底 `--surface-inset`，描边 1px `--line-input`，左内 12 放 16px 搜索图标（`--text-tertiary`），文字 14 `--text`，占位符 `--text-tertiary`。
- 右侧附属：快捷键胶囊 —— 11/500，`--surface` 底，1px `--line`，`--r-xs`，padding 0 4，`⌘` 与 `K` 之间 4。
- 悬停：描边 `--line-strong`。
- **聚焦**：底 `--surface`，描边 1px `--accent`，外环 `2px --focus`（offset 2）。聚焦是首屏默认态（新标签页打开即聚焦）。
- **有结果**：胶囊换成结果计数 `12 项`（12 / 400 / `--text-tertiary`，**纯文字，不加边框与底色**——胶囊的边框语义是"可按"，计数不可按），同时出现 16px 清除按钮（`--text-tertiary` → 悬停 `--text`）。
- **无结果**：输入框本身不变（不清空、不变红），反馈交给内容区的空状态。
- **演示模式徽标不放在输入框内。** 输入框尾槽只有两个状态（`⌘K` / 结果计数），塞第三个元素会把 40px 高的一行挤成三种宽度跳动。徽标放在顶栏右侧动作簇的最左侧：6px 圆点（`--spine-2`）+ 8 + `DEMO`（11 / 500 / `--text-tertiary`，`0.04em`），与动作簇 gap 12。
- 高度变化为 0——聚焦不放大、不浮起，避免输入时布局跳动。

### 6.3 区块标题（置顶 / 为你推荐 / 文件夹名）

- 一行，高 **20**，下边距 **8**，行内：标签 + 8 + 计数(12 `--text-tertiary`) + 12 + 1px 横线（`--line`，延伸到内容区右缘）。
- 标签 12 / 600 / `0.04em` / `--text-tertiary`。置顶区、推荐区、文件夹标题同一规格。
- 横线是**结构线**，不是装饰：它把三个区块在视觉上分层，让"置顶"与"全部"不会连成一片。
- 当前文件夹名作为区块标题时升一档：16 / 600 / `--text`，横线仍然存在。
- 区块之间垂直间距 **28**。

**行内文本控件（v0.2 补充，ux-spec V1/V2 签字项）**

区块标题行与区块末尾各允许**一个**文字控件，两者尺寸一致，规则如下：

| 位置 | 内容 | 规格 |
|---|---|---|
| 标题行**行尾**（横线右端，不紧跟计数） | `↩ 全部书签` 返回 | 13 / 500 / `--accent`；图标 14（stroke 1.5，`inherit` 颜色）+ gap 6；视觉高 20，**点击区高 28**（`padding: 4px 6px; margin: -4px 0 -4px -6px`） |
| 区块**最后一行卡片之下** | `还有 128 项` 追加 | 13 / 500 / `--accent`；计数部分 12 / 400 / `--text-tertiary`；高 28，`padding: 0 8px`，`margin-left: -8px` 让文字与卡片左缘对齐；距最后一行卡片 **12**（= 一个栅格 gap） |

- 返回控件放**行尾**而不是紧跟计数：标题行左簇只放身份信息（名称 + 计数），导航动作放行尾；这也让 1px 结构线保持完整，不被控件切断。
- 追加控件**禁止**加分隔线、边框、底色或做成整条通栏：它必须读作"下一行"，不是"区块的结束"——一旦加了线，每个区块就多出一个视觉终点，页面会被切成七八段。
- 追加控件悬停：底 `--surface-hover` + `--r-sm`，文字 `--accent-hover`。
- 两者在**没有更多内容时整体消失**（不显示"已全部显示"、不显示禁用态、不留空槽）。
- 一处只允许一个：标题行不出现第二个控件，区块末尾不出现第二个控件。
- **同一控件在所有区块必须同位置。** 内容区的「还有 N 项」和置顶区的「还有 N 项」不得一个在末行之下、一个在标题右侧——同一控件在相邻区块长得不一样，用户会以为是两个功能。
  位置即语义：末行之下读作"继续往下看"，标题右侧读作"展开这个区块"。置顶区是快捷方式层，用户在那里看到「还有 3 项」时想的是前者，所以只有末行之下这一个合法位置。（这条表述来自 ux 的 §11.5，比本文原稿更精确，已采纳。）
- 焦点环按 §7.1 全局规格（2px `--focus`，offset 2）。

### 6.4 书签卡片 — `card`

  - 焦点（键盘）：`2px --focus` 环，offset 2。

### 6.5 书签行 — `compact`

### 6.6 文件夹卡片

### 6.13 加载骨架

- 骨架显示规则（v0.3 修正，收敛 impl-brief 与本文的分歧）：**延迟 120ms + 最短停留 400ms**。

  - 超过 120ms 仍未返回：显示骨架；一旦显示，**至少停留 400ms**，避免 30ms 的闪入闪出。

## 7. 无障碍

### 7.1 焦点环

- 全局：`outline: 2px solid var(--focus); outline-offset: 2px; border-radius: 4px`。
- 输入类（搜索框、表单字段）：`outline-offset: 2px`，与 1px `--accent` 描边构成"双环"。
  这是刻意的：新标签页打开即聚焦，焦点必须第一眼可见。实现时不要为了"干净"把它弱化成单环。
- 焦点环对比度：浅色 5.08:1（画布）/ 4.53:1（侧栏底）；深色 8.95:1 / 8.35:1 —— 均 ≥3:1。
- `:focus-visible` 才画环；鼠标点击不画（`:focus:not(:focus-visible)` 显式清除 outline，防止浏览器默认框混入）。
- 菜单项不画环，改由「`--accent-soft` 底 + 1px `--accent` 内描边」表达（该组合的边界 8.73:1，满足状态可辨）。
- **显式例外（ux-spec V6 签字）：侧栏树行用 `outline-offset: -2px`。** 侧栏行宽等于容器宽，`+2` 的外环会被 `overflow` 裁掉。内环必须配 `border-radius: 4px`（与行圆角一致），否则四角会被切成方角。内环压在 `--surface-active` 上为 4.32:1，仍 ≥3:1，合规。这条例外只对侧栏树行生效，其他任何地方不得使用负 offset。

### 7.3 其他

- 可点击区域最小 28×28（菜单项高 30、卡片整卡可点、侧栏行高 30）。
- 不用颜色单独传达状态：错误 = 红描边 + 红文案 + 图标；选中 = 底色 + 色脊 + 字色三重。
- 焦点顺序：侧栏 → 搜索 → 内容区（行优先）→ 右下角控件。侧栏折叠时焦点直接进入搜索。
- 图标全部 `aria-hidden` 的装饰性 SVG + 相邻可见文本；纯图标按钮必须带 `aria-label`。
- 字体放大到 200% 时：卡片高度由内容撑开（min-height 68），不裁切标题。

## 8. 禁止清单

实现时出现以下任一项，即为偏离视觉方向，必须退回：

**颜色**
1. 渐变（线性、径向、锥形，含 `background-image: linear-gradient` 做"微光"）
2. 毛玻璃 / `backdrop-filter` / 半透明浮层
3. 紫色、靛蓝、以及任何饱和度 > 60% 的强调色
4. 彩色阴影（`box-shadow` 带色相）
5. 纯黑 `#000` / 纯白 `#FFF` 大面积底色
6. 除 6 色色脊外新增的任何装饰性色块

**形状**
7. 卡片圆角 > 6px、按钮胶囊化、大于 10px 的圆角
8. 卡片悬停上浮（`translateY` / `scale` / 阴影加深）
9. 除色脊、区块结构线、菜单高亮内描边之外的第四条"装饰线"

**元素**
10. 图标库（Font Awesome / Lucide / Heroicons 等）——所有图标内联 SVG，stroke 1.5
11. 任何外部资源：CDN、网络字体、Google favicon / DuckDuckGo icon 服务、遥测脚本
12. emoji 作图标
13. 大字标 / hero 区 / 欢迎语 / 品牌色大色块
14. 卡片上的常驻徽标（"新"、"热门"、角标、序号、折角）
15. 骨架屏的渐变扫光（shimmer）
16. 输入框错误态抖动、Toast 弹跳、任何 spring / bounce 缓动
17. 第二个招牌装饰细节

## 9. 交接说明

**给前端（frontend-engineer）**

- 所有颜色/尺寸/时长只从 `shared/tokens.css` 取，页面 CSS 里**不允许出现 hex 值**（`visual-preview.html` 是唯一例外，它是交付物本身）。
- 深度优先用「换底色 + 换描边」，不要新造颜色。
- 卡片网格统一用 `repeat(auto-fill, minmax(var(--card-min), 1fr))`，`--card-min` 绑定设置项「书签宽度」。
- 焦点环与 `prefers-reduced-motion` 在 tokens.css 已全局处理，页面里不要再写第二套。
- 深色必须同时支持两条路径：显式 `data-theme="dark"` 与 `prefers-color-scheme: dark`（tokens.css 已处理，但新标签页首帧要在 `<html>` 上尽早写入 `data-theme`，避免闪白）。

**给体验（ux-designer）**

- 右键菜单是书签/文件夹操作的**唯一入口**（除置顶区悬停的"取消置顶"），因此菜单分组顺序与禁用项逻辑需要严格定义。
- 拖拽排序与「仅在默认排序下可拖拽」的冲突，建议用 Toast + 一键切回默认，不要用模态。
- 空状态、无结果、错误态三者的**动作**必须明确且各自唯一。

**需要主理人拍板的取舍**

1. **推荐区使用 fixed compact 样式**，无视用户设置的 card/compact 偏好。理由：推荐是"建议"，与"我的书签"结构不同才不会混淆。若希望完全尊重用户设置，需接受推荐区与主网格同构、视觉上难以区分。
2. 区块标题后的 1px 结构线在 1920 宽下会显得略长；是否在内容区封顶后截断在 1560 处（当前方案）还是延伸到窗口右缘。
